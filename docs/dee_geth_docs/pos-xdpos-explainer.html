📡 What If a Validator Goes Offline? FAULT TOLERANCE

PoS and XDPoS networks are designed to be resilient. If a validator misses their slot (server crash, network issue), the protocol simply skips them and the next validator takes over.

🏛 XDPoS — XinFin Delegated PoS XDC NETWORK

XDPoS uses 108 elected validators. One becomes the leader for each block, creates it, and the others verify and sign. Once enough signatures are collected, the block is finalized permanently.

⚖ Consensus Mechanisms Compared

A quick overview of all four consensus types covered in this guide.

⛏ Proof of Work

Examples: Bitcoin, old Ethereum
  • Validators compete in a race
  • High energy consumption
  • Requires specialized hardware
  • Security from compute power
  • Slow finality

🔄 Proof of Stake

Examples: Ethereum, Cardano, Solana
  • Validators take turns
  • Low energy usage (~99% less)
  • No special hardware needed
  • Security from staked capital
  • Fast finality

🏛 Proof of Authority

Examples: Clique, Enterprise ETH
  • Pre-approved validators only
  • Very fast block times
  • Centralized trust model
  • Security from identity/rep
  • Instant finality

⚡ XDPoS

Examples: XDC Network
  • 108 elected validators
  • Leader rotation per block
  • Multi-layer verification
  • Cryptographic finality
  • High throughput
