// 01 — overview

What is Hive?

Hive is an automated testing framework originally built for Ethereum clients. It orchestrates Docker containers, connects them into a network, runs predefined tests, and generates reports — all without manual intervention.

XDC Network needed testing support for XDPoS consensus — so developers forked Hive and added XDC-specific clients and simulators.

// 03 — network comparison

Ethereum vs XDC

Both networks are EVM-compatible and support Solidity smart contracts — but they differ significantly in consensus and performance.

Feature ⟠ Ethereum ◈ XDC
Consensus Proof of Stake XDPoS
Block Time ~12 seconds ~2 seconds ⚡
Validators Thousands 108 Masternodes
Smart Contracts Solidity ✓ Solidity ✓
EVM Compatible Yes Yes
Genesis Format "difficulty": "1" "masternodes": [...]
⚠ Why some Ethereum tests fail on XDPoS
The genesis block format differs — Ethereum tests pass a difficulty field while XDC expects a masternodes list. This is expected. XDC-specific tests were added to handle this.

// 06 — new components in hive-for-xdpos

What Was Added?

The XDPoS fork introduced four new directories — two clients and two simulator suites.

01
clients/xdpos
XDC Core Node
The full XDC blockchain node. Participates in XDPoS consensus, creates and validates blocks, and executes smart contracts on the XDC EVM.
02
clients/xdc-gateway
XDC Gateway (RPC Proxy)
Acts as a reverse proxy between Ethereum tooling and XDC nodes — similar to how Nginx sits between users and backend servers. Forwards standard eth_* calls to the appropriate XDC node.
Application
(MetaMask / Web3)
→

→

03
simulators/smoke/xdc
XDC Smoke Tests
Basic sanity checks: do nodes start? Do they discover each other? Do peers connect? If two nodes can handshake ↔ the smoke test passes.
04
simulators/xdc/rpc-compat
RPC Compatibility Tests
Ensures every standard Ethereum JSON-RPC method responds correctly when called against an XDC node. This is what allows MetaMask, Web3.js, and blockchain explorers to work with XDC.
