What is Blockchain?

A distributed ledger maintained by multiple computers — no single point of control.

Technical Definition

A blockchain is a distributed ledger maintained by multiple computers. Every participant stores a copy of the ledger. Instead of trusting a central server, all participants agree on the same version of truth through consensus.

Real-life analogy

Imagine four bank branches — Mumbai, Delhi, Pune, Bangalore — each storing the same transaction ledger. When Dhiraj sends ₹1000 to Rahul, all branches update their copy simultaneously.

What is a Transaction?

A request submitted to the blockchain. Examples: sending coins, deploying contracts, calling smart contracts. Like submitting a bank transfer request.

Transaction Flow

04

What is a Block?

Definition

A block is a collection of verified transactions — like a page in a notebook. Each page stores multiple transactions. Pages link together to form the blockchain.

Analogy: Notebook pages = blocks. The notebook = blockchain. Each page references the previous page's number so the sequence cannot be tampered.
05

Consensus

The Problem Consensus Solves

If Node A says "Dhiraj sent 10 coins" and Node B says "Dhiraj sent 20 coins" — which is correct? Consensus is the mechanism that makes all nodes agree on a single version of truth.

Real-life analogy: Four accountants reviewing company accounts — only after all agree is the report finalized.
06

Consensus Types

⛏ Proof of Work

Nodes compete using computational power. First to solve a puzzle creates the next block.

Used by: Bitcoin

Very Secure High Energy
💎 Proof of Stake

Validators lock cryptocurrency as stake. Network selects validators based on staking rules.

Used by: Ethereum (post-Merge)

Energy Efficient Slashing Risk
🔐 Proof of Authority

Only approved, trusted validators can create blocks. No mining or staking required.

Used by: Private Geth / XDC

Fast Enterprise

XDPoS & Epochs

XDPoS — Delegated Proof of Stake

XDC's optimized consensus. Token holders vote for validators. Elected validators create blocks and govern the network.

Analogy: Shareholders elect board members → board members make decisions.

Epochs

An epoch is a fixed period used in consensus operations. At the end of each epoch, validator performance is reviewed and responsibilities may be updated.

Analogy: A work shift — after each shift, performance is reviewed.

Post-Merge Geth Architecture

The most important architectural shift in Ethereum's history — The Merge split Ethereum into two independent layers.

Before The Merge: Geth handled everything — execution AND consensus (PoW mining). One client did it all.
After The Merge: Ethereum was split into two separate layers communicating via the Engine API. Geth handles execution only; a separate consensus client handles PoS.

Post-Merge Architecture — The Two-Layer Model

❌ Before Merge (PoW Era)
  • Geth handled everything alone
  • Miners solved PoW puzzles
  • Single client = single point of failure
  • Extremely high energy consumption
  • geth --mine was enough
✅ After Merge (PoS Era)
  • Geth = Execution Layer only
  • Prysm/Lighthouse = Consensus Layer
  • Two clients → better security
  • ~99.95% less energy usage
  • Must run both clients together
