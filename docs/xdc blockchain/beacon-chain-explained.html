Section 01

Why PoW Needed to Go

Before the Merge, Ethereum used Proof of Work. Miners competed using massive computing power and electricity just to add one block.

Every miner on the network burned electricity racing to solve a puzzle. Only one wins; the rest wasted energy.

// After — Proof of Stake

Beacon Chain Selects
One Validator Proposes

A single validator is picked to propose. No wasteful competition. The Beacon Chain is the coordinator.

Section 04

Block Proposal → Attestation → Finality

One validator proposes, many attest (vote). When enough attestations are collected, the block is finalized — it cannot be reversed.

// the full block lifecycle
01 — Beacon Chain selects proposer
Random selection from the active validator set based on the current slot.
02 — Proposer builds block
Collects pending transactions from Geth's mempool, assembles the block body.
03 — Block broadcast to network
The proposed block is gossiped to all peers over the p2p network.
04 — Attestors vote (attest)
Committees of validators inspect the block and submit signed attestations saying it is valid.
05 — Supermajority reached (2/3+)
Once ≥66% of the committee attests, the block is considered justified.
06 — Block finalized
After two more checkpoint epochs, the block is finalized. Reverting it would require burning 1/3 of all staked ETH.
// REAL-LIFE ANALOGY: Exam Board Teacher A writes the result sheet (proposer). Teachers B, C, D, E sign off on it (attestors). Once the principal and enough teachers sign, it becomes official — finalized. No one can change Rohit's marks after that.
Section 05

Slots & Epochs

Time on the Beacon Chain is divided into slots (12 seconds each) and epochs (32 slots = ~6.4 minutes). One slot = one chance to propose a block.

// epoch 1 — 32 slots
● filled ● missed ● current
1 slot = 12 seconds  |  32 slots = 1 epoch (~6.4 min)  |  Finality checkpoint: every epoch
// ANALOGY: Office Hours Each 12-second slot is like a meeting slot in a calendar. Each epoch (32 slots) is like a working day. At the end of every "day," the Beacon Chain evaluates validator performance and computes rewards/penalties.
Section 06

Slashing — Punishment for Cheating

If a validator double-votes, proposes conflicting blocks, or acts maliciously, the Beacon Chain detects it and slashes them — destroying part of their stake and ejecting them.

// slashing simulator
Validator stake
32 ETH staked
SLASHING CONDITIONS
✗ Double voting — attesting to two different blocks in the same slot
✗ Surround voting — attesting in a way that surrounds a previous attestation
✗ Double propose — proposing two different blocks for the same slot
